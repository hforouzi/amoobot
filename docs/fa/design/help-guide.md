# راهنمای مشتری در مینی‌اپ — طراحی

وضعیت: **فقط طراحی، پیاده‌سازی نشده.** متن کامل و مرجع (انگلیسی): [docs/design/help-guide.md](../../design/help-guide.md). طرح همراه (سمت مدیر): [activity-group-and-daily-report.md](activity-group-and-daily-report.md).

مواردی که با **DECISION NEEDED (Gx)** مشخص شده‌اند باید پیش از اولین PR تأیید یا عوض شوند. راهنما جای بخش «راهنما» فعلی را می‌گیرد و **به‌طور پیش‌فرض روشن** است (فقط محتوای خواندنی اضافه می‌کند)؛ هر چیزی که رفتار دیگری را عوض کند (جواب «پشتیبانی» ربات) پشت سوییچ و پیش‌فرض خاموش است.

## ۰. آنچه امروز هست

- **بخش راهنما:** مسیر `miniapp_help` ← `MiniAppCustomerController::help()` قالب `templates/miniapp/view/help.html.twig` را با متن `bot.support` و یک کارت «ربات» و دکمهٔ بازگشت نشان می‌دهد. کلیدها در `translations/miniapp.{fa,en}.yaml`: `nav.help`، `help.title`، `help.bot_title`، `help.bot_text`، `help.back_to_bot`.
- **متن کهنه:** `help.bot_text` می‌گوید خرید و تمدید و حجم اضافه «فعلاً در ربات» است، درحالی‌که مینی‌اپ فروشگاه و صفحهٔ تمدید و حجم اضافه دارد.
- **نمایش متن پشتیبانی:** `bot.support` ممکن است HTML تلگرام باشد ولی مینی‌اپ آن را escape‌شده نشان می‌دهد، پس `<b>` به‌صورت متن دیده می‌شود.
- **ناوبری:** `MiniAppSection`، `MiniAppSectionProvider`، `CoreSections` (بخش `help`)، `MiniAppSections::isAllowed()` و `MiniAppSectionGuard`. راهنما همان بخش `help` با همان مسیر می‌ماند.
- **اپ‌های کلاینت:** `ClientApp` (نام، سکوها، الگوی لینک import، لینک فروشگاه، آیکون، یادداشت، ترتیب، فعال)، `AppDownload` (فایل یا لینک، سکو، نسخه)، `ClientPlatform` با تشخیص از user agent، بخش `apps` مینی‌اپ. موضوع «اتصال» **از همین رکوردها** ساخته می‌شود.
- **محتوای قابل‌ویرایش:** `BotMessageTemplate` (کلید، زبان، عنوان، متن، parse mode، دسته)، `BotTextResolver` با ترتیب: ردیف پایگاه داده ← زبان پیش‌فرض ← `translations/bot.*.yaml` ← پیش‌فرض اضطراری؛ فرمان‌های `app:bot-content:seed|list|missing`؛ بخش «محتوای ربات» در پنل با `BOT_TEXTS_MANAGE`.
- **سوییچ‌ها:** تابع Twig `wallet_enabled()`، `WalletSettings`، `ResellerSettings` (`claimsEnabled()`)، `SalesSettingsProvider`، `TrafficAddonSettingsProvider::canPurchase()`، پلن‌های تست، روش‌های پرداخت فروشگاه، `MiniAppLinks` (`miniapp.enabled`، پیش‌فرض خاموش).
- **لینک عمیق:** `StartPayloadRouter` (پیشوندها، `/start <payload>` ربات و `start_param` مینی‌اپ)؛ در `app.js`: `?service=ID`، `startapp=<payload>`، `a[data-nav]`، `a[data-open-link]`، `a[data-telegram-link]`.
- **قالب و جهت:** `entry.html.twig` برای `fa` جهت `rtl`؛ CSP بدون اسکریپت درون‌خطی.
- **کتابخانه:** نه Markdown و نه پاک‌ساز HTML در `composer.json` نیست.

## ۱. فهرست موضوع‌ها

هر موضوع یک شناسهٔ ثابت دارد (برای لینک عمیق، کلیدها و تست):

| شناسه | موضوع | نمایش وقتی |
|---|---|---|
| `start` | شروع: سه گام خرید ← نصب اپ ← وارد کردن لینک | همیشه |
| `buy` | خرید سرویس، کد تخفیف، پرداخت، اکانت تست | فروش تازه باز است (وگرنه پیام «فروش بسته است») |
| `pay` | روش‌های پرداخت فعال **فقط با نام** (کارت‌به‌کارت: رسید یا کد پیگیری و روند بررسی؛ درگاه؛ کریپتو؛ کیف پول) — هرگز شمارهٔ کارت | حداقل یک روش فعال |
| `wallet` | شارژ و پرداخت از کیف پول، موجودی و تاریخچه | کیف پول روشن |
| `connect` | نصب و اتصال برای هر سکو: اپ‌های فعال با لینک فروشگاه/دانلود و دکمهٔ import، سپس «کپی لینک اشتراک / اسکن QR» با ارجاع به «سرویس‌های من» (**خود لینک هرگز در راهنما نیست**) | همیشه |
| `usage` | دیدن حجم و روز باقی‌مانده، معنی «معلق» و «منقضی» | همیشه |
| `renew` | تمدید و انتقال حجم/روز باقی‌مانده طبق تنظیمات | تمدید باز است |
| `traffic` | خرید حجم اضافه | امکان خرید حجم اضافه |
| `troubleshoot` | وقتی وصل نمی‌شود: فعال بودن سرویس ← به‌روزرسانی اشتراک در اپ ← تغییر کانفیگ/سرور ← ساعت و تاریخ گوشی ← شبکهٔ دیگر ← import دوباره ← تماس با پشتیبانی با شمارهٔ سرویس (`#S…`، نه لینک) | همیشه |
| `claim` | لینک تحویل سرویس چیست، یک‌بارمصرف و تاریخ‌دار، فروشنده بعد از آن به لینک‌ها دسترسی ندارد | claim روشن |
| `faq` | پرسش‌های رایج (متن سیاست بازپرداخت را مدیر می‌نویسد) | همیشه (خالی ← پنهان) |
| `support` | متن فعلی `bot.support` و دکمهٔ بازگشت به ربات | همیشه |

## ۲. منبع محتوا

گزینه‌ها: (الف) فقط رشته‌های ترجمه — ساده ولی مدیر نمی‌تواند تغییر دهد؛ (ب) استفادهٔ دوباره از محتوای ربات (`BotMessageTemplate` با کلیدهای `guide.<شناسه>`) — همین امروز قابل‌ویرایش برای هر زبان با زنجیرهٔ جایگزینی و فرمان‌های seed/missing، ولی parse modeهایش مخصوص تلگرام است و پیش‌نمایش و سقف طول ندارد؛ (ج) جدول تازهٔ `guide_topic` — دقیق ولی تکرار (ب) با مهاجرت و پنل تازه.

**تصمیم: (ب)** با یک قالب مخصوص راهنما و بررسی‌های ویرایشگر: عنوان و متن هر موضوع کلیدهای `guide.<شناسه>.title` و `guide.<شناسه>.body`؛ پیش‌فرض‌ها به `fa` و `en` در `translations/bot.*.yaml` (بدون هیچ ردیف پایگاه داده کار می‌کند)؛ parse mode تازهٔ **`guide`** فقط برای کلیدهای `guide.*` با اعتبارسنجی (نحو، حداکثر ۴۰۰۰ کاراکتر متن و ۸۰ کاراکتر عنوان، قواعد `PlainText`)؛ **پیش‌نمایش** در صفحهٔ ویرایش؛ placeholder ناشناخته هنگام ذخیره رد می‌شود. **DECISION NEEDED (G2).**

## ۳. نمایش

**قالب «guide» (renderer خودی، بدون HTML از مدیر):** ورودی متن ساده است؛ renderer **اول همه‌چیز را escape می‌کند** و بعد فقط این‌ها را می‌شناسد: خط خالی = پاراگراف؛ `## عنوان`؛ `- مورد` و `1. مورد`؛ `**پررنگ**`؛ `[متن](https://…)` فقط https با `data-open-link`؛ `[متن](#connect)` لینک به موضوع دیگر؛ `{{ placeholder }}`؛ بلوک `::: if wallet` … `:::`. بدون HTML خام، تصویر، `javascript:` یا `data:`. یک تست خاصیت‌محور تضمین می‌کند هیچ ورودی تگی بیرون از فهرست مجاز تولید نکند. برای `bot.support` حالتی که فقط `b/i/u/s/a href=https` را نگه می‌دارد. **DECISION NEEDED (G3)**: قالب خودی (پیشنهادی) یا `symfony/html-sanitizer` و HTML محدود.

**placeholderها** (برای همهٔ مشتری‌ها یکسان): `{{ apps }}`، `{{ payment_methods }}`، `{{ support }}`، `{{ trial }}`، `{{ bot.brandName }}`. **هیچ placeholder شخصی وجود ندارد**؛ پس راهنما برای همهٔ مشتری‌های یک زبان یکسان است، چیزی از یک مشتری به صفحهٔ دیگری نشت نمی‌کند و قابل کش است. دادهٔ شخصی (لینک، موجودی، سرویس‌ها) در صفحه‌های موجود می‌ماند و راهنما به آن‌ها لینک می‌دهد.

**چیدمان:** کارت‌های `<details>`/`<summary>` (جمع‌شونده بدون جاوااسکریپت، سازگار با CSP)؛ RTL برای فارسی و LTR برای انگلیسی با ویژگی‌های منطقی CSS و `<bdi>` برای نام اپ و آدرس؛ تک‌ستونی، بدون جدول، هدف لمس ≥ ۴۴px، آدرس طولانی به‌جای متن دکمه است. **جست‌وجو:** فیلتر سمت کاربر در `app.js` روی عنوان‌ها و متن‌ها. **DECISION NEEDED (G4)**: در نسخهٔ اول (پیشنهادی) یا بعداً.

**لینک عمیق:** `/app/view/help?topic=<شناسه>[&platform=<سکو>]` (شناسهٔ ناشناخته ← فهرست). لینک‌ها از: «سرویس‌های من» خالی ← `buy`؛ سرویس منقضی/بی‌حجم ← `renew`/`traffic`؛ صفحهٔ اپ‌ها ← `connect` با همان سکو؛ پرداخت کارت‌به‌کارت ← `pay`؛ «کار نمی‌کند؟» در صفحهٔ سرویس ← `troubleshoot`. از ربات یا t.me: `startapp=guide_<شناسه>` با یک handler پیشوند `guide` در `StartPayloadRouter`، و `?guide=<شناسه>` روی آدرس دکمهٔ `web_app`.

## ۴. آگاهی از قابلیت‌ها و حالت‌های خالی

نمایش در کد و از همان providerهای فروشگاه حساب می‌شود، نه به دست مدیر: `wallet`، `new_orders`، `renewals`، `add_traffic`، `trial`، `claims`، `card_to_card`/`online`/`crypto`. موضوع پنهان در فهرست نیست و لینک عمیقش به فهرست برمی‌گردد. جمله‌های مربوط به قابلیت اختیاری در بلوک‌های `::: if` هستند؛ اگر مدیر بیرون از بلوک دربارهٔ کیف پول بنویسد، پیش‌نمایش صفحه را با هر سوییچ روشن/خاموش نشان می‌دهد و هشدار می‌دهد (هشدار، نه رد).

**بدون اپ کلاینت:** `connect` گام‌های عمومی را نشان می‌دهد (نصب یک اپ سازگار با V2Ray از فروشگاه اپ و import لینک از «سرویس‌های من») و «از پشتیبانی بپرسید از کدام اپ استفاده کنید». با اپ‌های تعریف‌شده، هر کارت نام، آیکون، دکمه‌های فروشگاه/دانلود (از شمارندهٔ `/d/{id}`) و یادداشت را دارد؛ دکمهٔ import به صفحهٔ سرویس می‌برد چون لینک سرویس لازم دارد و راهنما هرگز لینک را جاسازی نمی‌کند.

حالت‌های دیگر: بدون روش پرداخت ← `pay` پنهان و `buy` پیام بسته بودن فروش؛ `bot.support` خالی ← فقط دکمهٔ بازگشت؛ مینی‌اپ خاموش ← راهنما نیست و جواب پشتیبانی ربات تغییر نمی‌کند.

## ۵. سمت مدیر

- **ویرایش** در «محتوای ربات» (`BOT_TEXTS_MANAGE`، مدیر ارشد و مدیر): فیلتر «Guide»، ویرایش عنوان و متن برای هر زبان، پیش‌نمایش، بازگشت به پیش‌فرض (حذف ردیف). ترتیب و قواعد نمایش در کد است. **DECISION NEEDED (G5)**: پنهان کردن موضوع با خالی کردن متن (پیشنهادی: بله).
- **مستندات:** `docs/{en,fa}/miniapp-guide.md` (محتوای هر موضوع، راهنمای قالب، placeholderها، بلوک‌ها، لینک‌های عمیق مثل `https://t.me/<bot>?startapp=guide_connect`) و یک خط در `telegram-bot-content.md`.
- **ربات:** پشت `guide.bot_button_enabled` (**پیش‌فرض خاموش**): `handleSupport()` وقتی `MiniAppLinks::forTelegram()` آدرس دارد یک دکمهٔ `web_app` «📖 راهنما» اضافه می‌کند. دکمهٔ تازه‌ای در کیبورد اصلی نیست؛ دکمهٔ منوی تلگرام همچنان خانهٔ اپ را باز می‌کند.

## ۶. برنامهٔ تست

- renderer: همهٔ ساختارها؛ escape کردن `<script>`، `"><img onerror>`، `javascript:`، `data:`، `**` تودرتو؛ لینک موضوع ناشناخته؛ placeholderها؛ بلوک‌های `if`؛ متن RTL با آدرس لاتین؛ سقف طول؛ تست خاصیت‌محور.
- نشت: HTML راهنما برای دو مشتری متفاوت یکسان است؛ هیچ لینک اشتراک، توکن `/s/` یا توکن claim دیده نمی‌شود.
- سوییچ‌ها: هر پرچم روشن/خاموش ← موضوع و بلوک هست/نیست؛ لینک عمیق به موضوع پنهان ← فهرست.
- اپ‌ها: بدون اپ ← متن عمومی؛ هر سکو؛ اپ غیرفعال پنهان؛ دانلود از `/d/{id}`.
- زنجیرهٔ جایگزینی: بدون ردیف ← ترجمه؛ متن نامعتبر ذخیره‌شده ← متن سادهٔ escape‌شده، نه خطا.
- تست‌های کارکردی مینی‌اپ: `/app/view/help` برای مشتری ۲۰۰، `?topic=` کارت درست را باز می‌کند، ویژگی `dir`، لینک‌ها از سرویس‌های خالی و سرویس منقضی.
- ربات: سوییچ خاموش ← جواب پشتیبانی بدون تغییر؛ روشن و مینی‌اپ روشن ← دکمه هست؛ مینی‌اپ خاموش ← نیست. `startapp=guide_<شناسه>` معتبر/ناشناخته. همهٔ کلیدهای `guide.*` در `fa` و `en`.
